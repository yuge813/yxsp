# 元享真实一级邀请奖励 · 安装与验收

本包是基于本次提供的 `addons_bXzDR.tar.gz` 制作的增量覆盖包，不是整站安装包。不会自动连接生产站或发布小程序。只包含审核过的变更文件，不含站点配置、证书、密钥和用户数据。

## 本次规则

- 仅活动启用后新注册、通过有效邀请入口建立直属关系的新用户 B 可参与，历史用户和管理员改绑不补领。
- B 在注册日起 **7 个北京时间自然日内**首次完成正常签到，额外得 **5 金币**；B 在窗口内累计 **2 个不同自然日**签到后，直属邀请人 A 得 **10 金币**。注册当天计第 1 天。
- 每位 B 的每档奖励终身一次；A 只领取直属 B 的奖励，无二级奖励。分享动作、广告观看和广告点击不作为本活动奖励条件。
- 金币不能提现，可按小程序商品规则兑换；本功能不增加现金购买入口。
- 具体金额、窗口和名额以已发布活动及参与时的规则快照为准。后台保存新规则不重定价已确认参与者。
- 系统先预留两档奖励的总额，再确认参与。暂停只停止新增参与，已预留资格按原规则继续核验。过期释放未达标部分，已经发给 B 的首签奖励不追回。

## 部署顺序

1. 在生产数据库及当前 `addons/sage_dksy` 目录做备份，备份保存在站点公开目录之外。保留用户、签到、金币流水和邀请关系审计表。
2. 将 `MANIFEST.json` 与现站文件比对。`original_sha256` 是上传版本的原文件哈希；如果不一致，先人工合并站点后续修改，不要直接覆盖。新文件的 `original_sha256` 为 null。
3. 解压本包，把根目录 `addons/sage_dksy/` 合并到真实微擎根目录中的同名目录。不要覆盖站点配置或证书。PHP 至少 7.3；数据库需支持 InnoDB、事务和 GET_LOCK。
4. 使用该小程序账号的**所有者/站长**登录微擎，在邀请关系或增长运营页点击“真实邀请奖励管理”。也可在已登录后台访问：`./index.php?c=site&a=entry&m=sage_dksy&do=referral150`（必须选择正确账号）。管理员只读，安装和配置需要所有者权限。
5. 先执行管理页的安装/前置检查。只创建 5 张 `sage_dksy_v150_referral_*` 新表，不重建旧表、不改旧余额，不在小程序接口里自动建表。SQL 原文在 `addons/sage_dksy/migrations/referral150.sql`；表前缀以管理页适配为准，勿盲目导入到其他账号。
6. 前置检查通过后创建并启用新活动：B 首签 **5**、A 留存 **10**、不同自然日 **2**、窗口 **7**。设置合理的每日直属邀请上限、每日承诺金币预算和活动总承诺金币预算；预算必须为正。承诺预算按**确认参与当天**计入，包含已经发放及尚未发放的预留金币，与旧增长看板的人民币模拟预算分开。
7. 最后导入本次配套小程序前端，检查 AppID、`siteinfo.js` 站点地址、请求域名与合法业务配置，使用微信开发者工具重新编译、真机预览后提交审核。

只复制文件不会自动开启发币。未安装表、未启用活动或前置检查失败时，正常签到、阅读、广告激励、兑换和试用仍走原流程，新邀请活动不对外承诺奖励。

### 旧表前置条件

需要现有会员、签到、金币流水、V11 关系审计表及所需字段存在；参与事务的表必须为 InnoDB，签到时间须为 Unix 秒。若检查失败，先对照生产备份由站点维护人员处理旧表结构，不要绕过检查。本补丁不自动转换已有表引擎。

## 上线验收

请用真实测试微信账号执行，不使用旧会员假扮新用户，不直接改生产签到或余额。

1. A 打开推广页：看到当前真实活动规则、实际已到账金币、待达标和收益明细。复制链接/分享本身不发币。
2. B 从 A 的专属入口首次注册登录，首页显示新人参与状态。B 第一次正常签到，普通签到奖励按原配置发放，同时多一笔“邀请新人 · 首次签到奖励” **5 金币**流水；A 此时尚未得 10 金币。
3. 同一北京时间自然日反复进入、签到重试、刷新收益页：不会重复发 5 或 10 金币。
4. B 第二个不同北京时间自然日正常签到：A 的余额和金币流水新增“一级推广 · 好友留存奖励” **10 金币**，A 的收益明细显示已到账。奖励不会要求观看广告。
5. 暂停活动后，旧参与者和历史到账记录仍可见，已承诺且在窗口内达标的奖励可继续核验；新用户不再获得新资格。
6. 检查新表奖励流水与原金币流水、会员余额一致，预算预留和已发放总额不超上限。留存看板应计入注册当天午夜保存的真实签到记录。

未在本次环境执行微信官方编译、真机订阅或生产站部署；本地数据库与浏览器验收范围见配套测试报告。设计为固定一级签到留存奖励，不代表已获微信平台审核批准；发布时以实际类目、页面文案和平台审核结果为准。

## 故障与回退

- 奖励服务暂不可用时不把未到账显示为已到账，不影响普通签到结果；恢复后由本人推广页/新人页面重试核验。
- 先在后台**暂停新增参与**。不要删除活动、新表或金币流水，也不要直接扣回已发奖励。
- 已确认参与者仍有待兑现奖励时，应保留当前奖励引擎和接口继续核验。直接回滚这部分代码会暂时停止兑现；请先完成核对与未结承诺处理，再考虑完整代码回退。
- 仅需回退前端时可恢复备份前端；数据库记录和后台保留。后台 PHP 回退必须逐文件还原备份，新增表保留以供审计，禁止运行卸载或 DROP TABLE 清空历史。
